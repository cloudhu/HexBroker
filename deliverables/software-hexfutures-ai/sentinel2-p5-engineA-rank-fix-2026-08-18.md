# P5 引擎 A 跨时间 rank 修复与组合重估报告

**日期**：2026-08-18 ｜ **流程**：工程师实现 → QA fresh-eyes 复核（VERIFIED）→ 主理人终裁

## TL;DR

| 项目 | 结论 |
|---|---|
| 缺陷 | `engine_a_targets` 用 `exp_ret.rank(pct=True)` **全表跨时间排序**，而信号缓存覆盖率不均（2019-21 日均13品种 / 2026 仅2.2品种/天），top30% 阈值被扭曲 |
| 修复 | 按日横截面 rank（`groupby(ts).rank(pct=True)`）+ 稀疏日最小品种数过滤（S2: min=3） |
| 修复效果 | 引擎 A **全样本 0.484→0.594、IS 1.162→1.309 显著改善**；但 **OOS 如实报告更差（-0.19→-0.34）**——瓶颈在信号端而非排序口径 |
| 组合重估 | S2 A25/B75 OOS **0.812** < 旧版基线 0.940（旧版 OOS 是伪影）；**纯引擎 B OOS 1.260 > 任何含 A 组合** |
| **主理人终裁** | **① 采纳 S2 修复（拒绝回退旧版）② 引擎 A 降权至 ≤15% 或暂以纯 B 运行 ③ 权重决策一律用 S2 口径，禁用旧版数字** |

## 一、缺陷确认（QA 发现 + 主理人核实）

`scripts/p3_combo_backtest.py` 的 `engine_a_targets`：
```python
sig["rank_pct"] = sig["exp_ret"].rank(pct=True)   # 全表 7952 行一次性排序 ← 缺陷
```

信号缓存 `signals_cache18_grouped_v2.parquet` 是 walk_forward 嵌套子窗输出，**覆盖率极度不均**：

| 年份 | 日均品种/天 | 备注 |
|---|---|---|
| 2019-2021 | 12.7~13.2 | 71% 天数 ≥15 品种 |
| 2022 | 8.0 | 覆盖率下降 |
| 2024 | 5.7 | 27.4% 天数 <3 品种（2022+） |
| 2025 | 5.9 | |
| **2026** | **2.2** | 极度稀疏 |

全表 rank 后果：早期 17 品种的天和后期 2 品种的天混合排序，top30% 阈值被早期高 exp_ret 主导 → **不是真正的"每日截面 top30%"**。

## 二、修复实现（scripts/p5_engineA_cross_section.py）

新增 `engine_a_targets_cs(prices, top_k, min_symbols)`：
- **按日横截面 rank**：`sig.groupby("ts")["exp_ret"].rank(pct=True, ascending=True)`（[0,1] 越大越强）
- 做多：`rank_pct >= 1 - top_k`（每日 top30%）
- 稀疏策略：S1 无限制 / S2 min=3 / S3 min=5 / S4 min=8（当日不足 → 整日空仓，无前视）

## 三、单引擎对比（完整 BacktestEngine 口径，QA 复跑逐字节一致）

| 策略 | 全样本 Sharpe | OOS Sharpe | OOS MaxDD | 做多天数占比 |
|---|---|---|---|---|
| 旧版（全表 rank） | 0.484 | **-0.192** | -10.7% | 58.0% |
| S1 截面 min=None | 0.601 | -0.318 | -12.4% | 63.4% |
| **S2 截面 min=3** | **0.594** | **-0.337** | -13.0% | 59.2% |
| S3 截面 min=5 | 0.594 | -0.322 | -12.5% | 47.5% |
| S4 截面 min=8 | 0.602 | -0.295 | -11.8% | 45.9% |

**解读**：修复后全样本/IS 显著改善（IS 1.162→1.309），说明旧版 rank 确实污染了 IS 评估；
但 OOS 如实恶化（-0.19→-0.34，主要在 2024H2）——**引擎 A 的 alpha 瓶颈在信号端（覆盖率不均 + exp_ret 校准），不在排序口径**。

## 四、组合重估（P4-1 网格 × 修复后引擎 A=S2）

| 配置 | 全样本 Sharpe | OOS Sharpe | OOS MaxDD | 备注 |
|---|---|---|---|---|
| 旧版 A25/B75（P4-1 基线） | 0.951 | **0.940** | -5.2% | 伪影基线 |
| **S2 A25/B75** | **0.972** | **0.812** | -6.9% | 修复后最优 |
| S2 A30/B70 | 0.975 | 0.717 | -7.1% | |
| S2 A40/B60 | 0.970 | 0.530 | -7.4% | |
| **纯引擎 B** | **0.927** | **1.260** | **-6.7%** | QA 补充验证 |

**关键发现（QA 补充验证）**：**纯引擎 B OOS Sharpe 1.260 > 网格内每个含 A 组合**，且随 A 权重单调下降（S2: A25 0.812 → A40 0.530）——**当前信号形态下引擎 A 是组合的 OOS 负贡献者**（低权重仅平滑回撤：纯B MaxDD -6.7% vs A25 -6.9% 略优已不明显）。

## 五、主理人终裁

1. **采纳 S2 修复**：`engine_a_targets_cs(min_symbols=3)` 成为引擎 A 标准实现。**拒绝回退旧版**——旧版"更好看的 OOS"是跨时间 rank 伪影，用错误口径做权重/风险决策在量化生产中不可接受（QA 意见一致）。
2. **引擎 A 降权**：短期组合权重 A ≤ 15% 或**暂以纯 B 运行**；中期在信号端修复（覆盖率/校准）前不将 A 视为贡献者。
3. **权重决策基准**：一律使用 S2 口径数字，禁用旧版数字做任何选优。
4. **登记后续**：引擎 A 信号端修复方向——信号覆盖率提升（walk_forward 子窗拼接完整性）+ exp_ret 校准复核。

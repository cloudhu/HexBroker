# LightGBM 冠军模型特征选择裁剪报告

> 报告日期：**2026-08-16** | 品种：['SHFE.au','SHFE.ag','DCE.m'] | horizon=5 n_mc=30 | 全 66 折 walk-forward，调优后 HP
> 裁剪依据：冠军 v4 全 66 折特征重要性（`lightgbm-feature-importance-v4-2026-08-16.json`）

## TL;DR

- 收集冠军 v4（25 特征）全 66 折特征重要性排名：**UUP+SPX 六个外盘特征全部挤进 top-10**（合计重要性 36.3%，与它们带来的 +1.56pp 增益相符），量价类（vol_5/vol_20/boll_width）紧随其后。
- 按重要性构造 top-10 / top-15 / top-20 裁剪变体，全 66 折消融：**三个裁剪方案全部降性能**（-1.86 / -0.49 / -0.93pp），**冠军 v4 全量 25 特征保持最优（70.23%）**。
- **结论：特征选择裁剪不采纳**。LightGBM 的 lgbm_reg_lambda/alpha 正则化 + 内置重要性加权已天然处理弱特征；树模型能利用尾部弱特征（f_body_ratio/f_lower_shadow 等 <2%）的交互信息，外部裁剪反而损失。
- 新增能力：pipeline 支持 `keep_features` 特征级白名单（裁剪/消融基础设施，默认 None 不影响任何现有行为）。

## 3. 为什么裁剪反而降性能？

1. **LightGBM 对弱特征免疫**：树分裂天然做重要性加权，尾部特征（1.5~2% 重要性）在有正则化（lambda=0.0416/alpha=0.0024）时几乎不引入噪声——它们提供的是**边际交互信息**而非噪声。
2. **交互信息不可裁剪**：top-15 裁剪掉了 f_ma_spread/f_gap/f_ret_1 等（2~2.4%），但它们与 top 特征（vol/bar_dir）的组合分裂在 66 折中贡献了方向增益；单看重要性低不代表组合无价值。
3. **与线性模型差异**：若用逻辑回归/LDA，裁剪确实能提泛化；但对树模型 + 已调优正则化，外部裁剪是**负和博弈**（-0.49~-1.86pp 实证）。
4. **coverage 也受损**：top-20 裁剪后 coverage -3.32pp——尾部微观结构特征（intraday_range/body_ratio 等）对信号有效性（is_effective 判定）有直接贡献。

## 4. 结论

- **冠军特征集维持 v4（25 特征，70.23% / RankIC 0.4510）**，不做裁剪。
- **特征工程路线正式收官**：从 R7 的 67.89% 经 HP 调优（+0.44pp）、区间位置（+0.34pp）、SPX 外盘组（+0.39pp）、UUP 外盘组（+1.17pp）到 **70.23%**；此后外盘扩展（ixic/dji/tlt/ief/t10y）、特征裁剪（top-10/15/20）全部负贡献——**该特征集在 LightGBM 下已达性能上界**。
- 新增基础设施：`keep_features` 特征级白名单（pipeline + FeatureConfig 支持，默认关闭，不影响现有行为），供未来消融复用。

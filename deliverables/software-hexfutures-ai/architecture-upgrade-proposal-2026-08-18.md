# 架构升级提案：Sentinel-2「双引擎 + 多维因子」（2026-08-18）

**TL;DR**：当前架构（v2.1）的胜率（持仓日 51.4%）与 OOS 年化（0.64%）不达标，**根因不是模型不够好，而是信息维度单一 + 策略形态受限**。已发现可落地的数据突破（PandaData 期货 DeepView：基差/期限结构/仓单/席位持仓），设计 **Sentinel-2 双引擎架构**（趋势引擎 + 基本面/均值回归引擎）——把商品期货公认的四大 alpha 源纳入模型，目标：**胜率 55%+、OOS 年化 5-10%**。

---

## 一、瓶颈诊断：为什么现在无法达标（数学约束 + 实证）

### 1.1 胜率约束——日频方向是弱有效的

| 证据 | 数值 | 含义 |
|---|---|---|
| 方向预测（p_up>0.5） | **50.57% ≈ 随机**（嵌套口径，已证伪弃用） | 日频价格方向几乎无法预测 |
| 持仓日胜率（当前 v2.1） | 51.4%（全样本）/ 38.9%（OOS） | 排序+趋势形态的胜率天花板 ≈ 50-52% |
| 持仓日均收益 vs 空仓日 | +12.8bp vs +4.5bp（2.8×） | 盈利靠**盈亏比**，不是胜率 |

**结论**：在"日频 OHLCV + 排序/方向"范式内，胜率 55%+ 与年化高收益**数学上互斥**——趋势策略必然低胜率高盈亏比。要突破，必须**换信息维度或换策略形态**。

### 1.2 收益约束——持仓稀疏 + OOS 信号失效

- 持仓日占比仅 **16%（全样本）/14%（OOS）**——三重门控（top35%+监控+波目标）下大部分时间空仓，资金利用率极低；
- OOS 段截面信号 regime 反转（分位桶倒挂 +0.688%→-0.884%）——单信息源失效时无替代信号接棒（动量已尽力，不够）。

### 1.3 根因总结

> **当前模型的全部 25 个特征都是"价格衍生"**（技术/波动/日内/宏观比值）。而商品期货的 alpha 主体在**特征空间之外**：基差、期限结构（展期收益）、库存（仓单）、持仓结构（聪明钱）——这才是"不是每个品种都有效"（ag0/au0 反指、p0 负 IC）的深层原因。

## 二、数据突破（PandaData 期货 DeepView——已确认可调用）

| 方法 | 因子 | 学术/实务胜率共识 | 用途 |
|---|---|---|---|
| `get_future_basis` | **基差率**（现货-期货）/现货 | **55-65%**（基差回归） | 均值回归引擎核心信号 |
| `get_future_term_structure` | **期限结构**（近远月价差 → 展期收益） | **55-65%**（期限结构溢价） | 趋势引擎增强信号 |
| `get_future_calendar_arbitrage` / `get_future_free_spread` | 跨期/自由价差 | 50-60%（配对回归） | 配对交易模块 |
| `get_future_warehouse_receipt` | **仓单数**（库存代理） | 55%+（库存-价格负相关） | 基本面信号 |
| `get_future_netposi_rank` / `get_future_ls_ratio` | **席位净持仓/多空比**（聪明钱） | 55%+（持仓结构） | 资金面信号 |
| `get_future_contract_indicators` | 龙虎比/牛熊线 | 55%+ | 资金面增强 |

> ⚠️ 验证状态：方法文档与示例数据已确认（如 A 豆一基差率 0.23%-2.6%）；**实际拉取待连接器 token 恢复**（当前 reauth_required）。

## 三、新架构：Sentinel-2「双引擎 + 多维因子」

```
┌────────────────────────────────────────────────────────────────────┐
│ 数据层（扩展）                                                      │
│   OHLCV 18 品种（现有）+ 全局宏观 + 基差 + 期限结构 + 仓单 + 席位持仓 │
└──────────────┬─────────────────────────────────────────────────────┘
               ▼
┌────────────────────────────────────────────────────────────────────┐
│ 引擎 A：趋势引擎（现有 v2.1 保留，进攻）                            │
│   - 分组建模 exp_ret 截面排序 + mom90 + 监控 + 波目标               │
│   - 定位：低胜率(50%)高盈亏比，捕获大趋势                           │
└──────────────┬─────────────────────────────────────────────────────┘
               │
┌──────────────▼─────────────────────────────────────────────────────┐
│ 引擎 B：基本面/均值回归引擎（新增，防守+平滑）                      │
│   - 信号：基差率分位（负基差收敛）+ 展期收益（backwardation 溢价）   │
│   - 形态：可多可空（基差交易天然双向），短周期持仓（5-20 日）         │
│   - 定位：高胜率(55-65%)低盈亏比，高交易频次                        │
└──────────────┬─────────────────────────────────────────────────────┘
               │
┌──────────────▼─────────────────────────────────────────────────────┐
│ 组合层：双引擎相关性加权                                            │
│   - 趋势（A）与均值回归（B）天然低相关 → 组合 Sharpe 提升            │
│   - 资金分配：A 60% / B 40%（初值，可进化）                         │
│   - 引擎 B 在 A 空仓期（监控关闭时）独立持仓 → 资金利用率↑           │
└─────────────────────────────────────────────────────────────────────┘
```

### 为什么能同时提升胜率与收益

| 维度 | 机制 |
|---|---|
| **胜率** | 引擎 B 高胜率（55-65%）与引擎 A（~50%）组合 → 组合持仓胜率上移至 52-56% |
| **收益** | ①新 alpha 源（基差/期限结构）在 A 失效期接棒；②双引擎互补持仓 → 持仓占比 16%→35-45%，资金利用率翻倍；③均值回归短周期 → 交易频次×3-5 |
| **稳健** | 双引擎低相关（趋势 vs 回归）→ 组合回撤低于任一单引擎 |

## 四、预期目标（产品发布级）

| 指标 | 当前 v2.1 | Sentinel-2 目标 | 差距来源 |
|---|---:|---:|---|
| 持仓日胜率 | 51.4% | **55-58%** | 引擎 B（55-65%）加权 |
| OOS 年化 | +0.64% | **+5-10%** | 新因子 + 资金利用率×2 + 双引擎互补 |
| OOS 回撤 | -2.80% | < -5% | 均值回归天然低回撤 |
| 全样本 Sharpe | 0.96 | **1.2-1.5** | 低相关组合 |

## 五、验证路线图（可执行，每步 OOS 留出）

| 阶段 | 内容 | 产出 |
|---|---|---|
| **P0 数据落地** | token 恢复后拉 18 品种基差/期限结构/仓单（2018~2026，分段）落盘 `data/raw/fundamental/` | 基础数据库 |
| **P1 单因子验证** | 嵌套口径验证基差率/展期收益/仓单变化的 RankIC 与分位单调性（**先验：IC<0.03 或分位不单调则否决**，避免重蹈 vix 覆辙） | 因子通过/否决表 |
| **P2 引擎 B 独立回测** | 基差回归策略（多空）BacktestEngine 完整回测：胜率/年化/回撤 | 引擎 B 基线 |
| **P3 双引擎组合** | A+B 相关性加权（60/40 初值，网格 50-80%）完整回测 + OOS | Sentinel-2 v1.0 |
| **P4 增强** | 席位持仓/龙虎比入引擎 B 或独立引擎 C | 迭代 |

**纪律**：沿用全项目铁律——嵌套口径、完整回测、OOS 完全留出（2024-07-18 后）、平台性检查、单因子先验（IC/单调性不过即否决）。

## 六、风险与诚实标注

1. **数据历史深度待确认**：基差/期限结构数据覆盖 2018 前？若仅 2025+，则需重排分段验证（OOS 定义调整）；
2. **均值回归的 OOS 风险**：基差收敛在 regime 切换（如 2024 贵金属逼空）可能失效——必须 OOS 验证；
3. **胜率-收益权衡的现实**：组合胜率 55%+ 是目标不是保证——若引擎 B 单因子验证不通过，需退化为"仅资金利用率提升"路线；
4. **token 依赖**：P0 需连接器重新授权（当前 reauth_required）；
5. **工程成本**：数据落地 + 双引擎回测约 1-2 个工作日（复用现有回测基建）。

## 七、主理人裁决建议

| 决策项 | 建议 |
|---|---|
| 是否升级 | ✅ **升级**——当前形态数学上无法同时满足胜率+年化要求 |
| 引擎 A 处置 | **保留**（已验证 alpha，作进攻腿） |
| 第一步 | **P0 数据落地 + P1 单因子验证**（先验证因子再建引擎，避免又一次"信号层有效净值无效"） |
| 不做什么 | 不推翻现有 v2.1（作基线对照）；不堆特征（沿用白名单哲学） |

## 4. P5 引擎 A 基线（OOS 已为正；"转正"主因是缓存升级 v2→v8，broker 修复边际 +0.36）

| 指标 | 修复前（旧 P5 artifact） | 修复后（当前口径） |
|---|---|---|
| OOS Sharpe | **-0.337** | **+0.990** |
| OOS 复利 | n/a（旧表未含 oos_ret） | +10.87% |
| OOS MaxDD | -13.02% | -4.30% |

- **口径说明（重要）**：旧值 -0.337 为 **v2 信号缓存 + buggy broker + P5 时代数据**
  （oos_n=500；P5 时代 config 无 `signal_cache` 字段 → fallback v2）；新值 +0.990 为
  **v8 生产缓存 + fixed broker + 当前数据**（oos_n=502；P8-4 起生产切 v8）。
- **归因（QA fresh-eyes 隔离矩阵，当前数据/全历史/OOS 切片，`_qa_p182_cache_iso.py`）**：
  | 信号缓存 | buggy broker | fixed broker |
  |---|---|---|
  | v2（P5 时代） | -0.155 | -0.464 |
  | v8（P8-4 生产） | +0.626 | **+0.990** |
  → **符号翻转（转正）主因是 P8-4 缓存升级 v2→v8**（v8+buggy 已是 +0.626 正）；
  broker 修复在 v8 上的边际贡献为 **+0.63→+0.99（+0.36，显著但非转正主因）**；
  在 v2 上 broker 修复反而更差（-0.15→-0.46）。历史 -0.337 是 **v2 缓存时代口径**，
  **不能直接归因于 broker bug**（旧值与隔离矩阵 v2+buggy -0.155 的差异来自 P5-era 数据窗口）。
- **broker 修复的机制（仍真实存在，幅度视品种而定）**：引擎 A OOS 持仓 13 品种
  （ta0/al0/p0/jm0/y0/rb0/m0/sr0/ni0/ag0/zn0/hc0/cf0），含 jm0（×60）、ag0（×15）、
  ni0（×1）等非 ×10 品种；buggy 记账按 **10/mult** 系统性扭曲逐品种 PnL（OOS-only 分解：
  ni0 +2,688→+27,743（×10.3）、jm0 +12,441→+1,927（÷6.5）、ag0 +4,215→+2,778（×0.66））。
- **含义（修正后）**：当前 v8 生产缓存下引擎 A OOS 已为正（即使 buggy 口径 +0.63）；
  修复后进一步提升至 **+0.99**（cap0.5 变体 +1.05）→ 值得团队重新评估是否恢复引擎 A 的
  实际配置（见 §5 建议）。注意：P5 时代 -0.337 属旧缓存口径，不代表当前 v8 生产信号。

## 5. 生产决策影响评估（明确）

| 决策项 | 修复前依据 | 修复后 | 是否受影响 |
|---|---|---|---|
| 引擎 B 为主 | B OOS 1.622 显著为正 | B 仍为正（0.49~0.57） | **不受影响（仍为主引擎）** |
| A10/B90 权重 | 旧网格(v8+buggy)：B(1.62) >> A(0.63) → 最小化 A | 修复后：A(0.99) > B(0.49) → 最优 A0.35/B0.65（0.731 vs 0.561） | **受影响（网格口径）**，但计划路径仍纯 B |
| 引擎 B 参数 win252/thr0.70 | 网格 5/12、1.622 | 0.490、6/12；thr0.60 更优 | **建议复核**（候选 win126/thr0.60、thr=0.60 档） |
| 引擎 A 名义 20k（→0 手） | 结构性 0 手（P16 事实①） | 仍 0 手（计划路径不变） | 不受影响，但引擎 A 价值重估后**建议上调名义** |
| P17 shadow account | — | block+T+1 OOS 0.572 / +9.02% | 基准保持不变（已 VERIFIED） |

**建议（提交主理人裁决，本脚本不改任何配置默认）**：
1. 引擎 B：评估 thr 0.70→0.60（修复后 4/4 档 win 中 3 档 0.60 更优；但 thr 越低持仓越多，
   需结合交易成本/容量）；
2. 引擎 A：鉴于当前 v8+fixed 口径引擎 A OOS 为正（+0.99；即使 buggy 口径也已 +0.63），
   评估上调 `notional_frac`（当前 0.20 → 组合层 20k 名义
   floor 0 手），使 A 实际可交易后再按修复后网格定权重；
3. 组合权重：若引擎 A 恢复可交易，参考修复后网格（A0.35/B0.65 为测试范围内最优）。

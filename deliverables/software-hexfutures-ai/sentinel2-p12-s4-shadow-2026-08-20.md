## 二、影子监控脚本

### 2.1 脚本结构

```
scripts/p12_s4_shadow_monitor.py
├─ load_close_panel()      # 18 品种日线 close 面板（data/raw/processed/{sym}/1d）
├─ load_signals()          # 信号缓存（symbol/ts/p_up/exp_ret/is_effective）
├─ add_fwd_returns()       # fwd5 = close[t+5]/close[t]-1（品种内交易日 shift，仅已实现收益）
├─ daily_cs_ic()           # 每日截面 Spearman(exp_ret, fwd5)，仅 OOS 且 >=3 品种
├─ daily_hit_rate()        # 每日 exp_ret 截面 top30% 品种 fwd5>0 占比
├─ overlap_corr()          # rt30 vs v2 同期信号每日截面 Spearman + 合并表
├─ pooled_spearman()       # 63 窗池化 Spearman（漂移主指标）
├─ cache_metrics()         # 单缓存指标汇总（含 63 窗滚动序列）
├─ corr_metrics()          # 相关性汇总
├─ build_baseline()        # --baseline：生成 artifacts/p12_s4_shadow_baseline.csv
├─ run_monitor()           # --monitor：重算对比 + 触发评估 + 漂移判定
├─ evaluate_trigger()      # 主触发：尾部连续窗口优势计数
└─ evaluate_drift()        # 漂移：绝对告警 + 相对基线回落预警
```

### 2.2 指标口径（已定案）

| 指标 | 口径 | 说明 |
|---|---|---|
| **滚动 OOS 截面 IC** | 每日截面 Spearman(exp_ret, fwd5)（当日品种数 >= 3，仅 OOS >= 2024-07-18）→ 63 窗滚动均值 | 与生产引擎 A 的每日截面 rank 一致；63 个**有效 IC 日**（信号稀疏，非 63 自然交易日——v2 末 63 IC 日跨 2025-11-03 ~ 2026-06-10） |
| **滚动命中率** | 每日 exp_ret 截面 top30% 品种 fwd5>0 占比 → 63 窗滚动均值 | 与引擎 A top_k=0.30 一致 |
| **信号相关性（漂移核心）** | 主：63 窗**池化** Spearman（最近 63 个重合日的全部 (symbol,ts) 对一次计算）<br>辅：每日截面 Spearman 的 63 窗滚动均值 | 池化稳健；日截面在 n=3 时粒度粗糙（只能取 {-1,-0.5,0.5,1}），仅作辅助 |

**口径铁律遵守**：漂移/IC 指标只用 t 及以前信息（滚动窗口尾随）；fwd5 仅用已实现
收益（K 线覆盖的日期）；只读分析（不重训、不改缓存/数据/hexbroker 包）。

**口径边界说明（QA Round 2 文档级建议并入）**：
- **对比窗口盲区**：触发比较只覆盖两缓存**共有的对齐日期**（v2 与 rt30 同日同品种
  均有信号才计入）。rt30 独有尾部（2026-06-12 ~ 2026-07-27，v2 无同期信号）不在
  对齐对比窗口内——该尾部 rt30 的 IC/命中率作为补充信息报告，但不参与 rt30 vs v2
  的胜负计数。
- **池化 63 窗为长期平均**：63 个重合日因信号稀疏跨约 **1.8 年**（非 63 自然交易
  日），池化 Spearman 反映长期平均相关水平，对短期漂移（数周级）不敏感——短期
  分化需配合日截面滚动均值（辅指标）观察。

### 2.3 复核触发条件（登记）

| 触发 | 条件 | 动作 |
|---|---|---|
| **主触发（升级评估）** | 新数据出现（2026-08-18 后 K 线刷新 / 缓存重建）后，rt30 滚动 OOS IC 连续 >= 5 窗 > v2 **且** \|IC\| > 0.03；**或** 滚动命中率连续 >= 5 窗 > v2 且 > 0.50 | 进入升级评估流程（§四） |
| **漂移告警** | 池化信号相关性 < 0.50（绝对） | 两引擎分化，需人工确认 |
| **漂移预警** | 池化信号相关性 < 基线池化值 - 0.15 | 观察趋势，人工复核 |

**漂移阈值重标定说明（重要）**：P7 登记的绝对阈值 0.8 经基线标定发现**基线即误报**——
(1) 日截面相关性在 n=3 时粒度粗糙（只能取 {-1,-0.5,0.5,1}），63 窗滚动均值 0.346
远低于 0.8，属方法学伪警报；(2) 池化 Spearman 0.604 也低于 0.8——这是 S4 改变重训
节奏（test_len 60→30）后与 v2 的**真实信号分化**（预期内，非异常）。故重标定为：
绝对告警 0.50、相对基线回落 0.15 预警。原始 0.8 阈值保留在登记项中但标注"基线即误报，已重标定"。

### 2.4 监测频率建议

- **数据刷新后运行**（推荐挂自动化）：`python scripts/p12_s4_shadow_monitor.py --monitor`
- **缓存重建后必跑**：重建 v2/rt30（或新增 v8 口径 S4 候选）后，先 `--baseline` 更新基线再 `--monitor`
- 运行时 0.9s（基线）/ 0.9s（复核），开销可忽略

## 四、升级流程（触发后）

```
主触发（fresh-OOS 确认）
  → 1. 完整 BacktestEngine 口径重估（滑点1tick+费0.005%+保证金12%+CONTRACTS18，
       引擎 A 截面 rank + S2 min=3，组合 A15/B85 权重网格——复用 p5/p7 工具链）
  → 2. QA 统计检验（块自助法 block=21 B=5000 复用 P7 QA 方法 + 滚动 Sharpe 胜率）
  → 3. 主理人终裁（显著改善 + 覆盖率/机制自洽 → 升级；否则维持影子状态）
```

升级评估的前提是 **fresh-OOS 数据确认**：触发条件必须由 2026-08-18 后新数据
（新 K 线使尾部信号可评估 / 缓存重建产生新信号）的滚动窗口满足，**现有数据上的
回顾性触发不算数**（见 §五）。

## 五、如实报告（当前状态判定）

1. **无 fresh-OOS 数据**：K 线最新 2026-08-17；v2 信号至 2026-06-11、rt30 至
   2026-07-27，全部早于 fresh-OOS 起点（2026-08-18）。基线快照 = 现有数据的
   最近滚动窗口表现；fresh-OOS 复核待数据刷新。
2. **现有数据回顾性信号（不构成升级依据）**：`--monitor` 显示主触发条件在现有
   数据上已满足——rt30 滚动 IC 连续 **7 窗** > v2 且 |IC|>0.03（阈值 5 窗）、
   命中率连续 3 窗 > v2（未达 5 窗）。但该窗口位于 **P7 OOS 段内**（对齐比较
   截止 v2 末值 2026-06-10），P7 QA 块自助检验已判 p≈0.49 不显著；且 v2 近期
   滚动 IC 深度为负（-0.31）、命中率 0.375（top30% 选中品种 62.5% 时间亏损），
   rt30 接近中性（-0.03/0.528）——**"rt30 优于 v2"主要源于 v2 近期恶化，而非
   rt30 转正**，与 P7"改善主因降波动、均值由负转平"结论一致。故不触发升级。
3. **漂移监测状态**：池化信号相关性 0.604（基线值）→ DRIFT_OK。rt30 与 v2
   信号为**中等相关**（非极高相关）——两缓存真实分化，影子跟踪**有区分度**
   （非"无信号"情形）。相关性为静态缓存快照，漂移告警在缓存重建/新增信号后
   才有实际意义（脚本已内置相对基线的预警逻辑）。

## 六、最终建议

1. **S4 影子跟踪框架就绪（IS_PASS: YES）**：脚本 + 基线快照 + 触发/升级流程已落地；
   当前无 fresh-OOS 数据，影子状态为"待数据刷新确认"。
2. **监测频率**：数据刷新后运行 `--monitor`（可挂自动化，单次 <1s）；缓存重建后
   必先 `--baseline` 更新基线。
3. **延伸建议（不在本次范围）**：S4 候选未在 v8 口径下重训过。若后续以 v8 为生产
   基线做影子对比，需在 v8 口径下重训 rt30 候选并重建基线（脚本支持任意两缓存

   连续 5 窗优势 + QA 统计检验显著 + 覆盖率/机制自洽，方可进入主理人终裁。

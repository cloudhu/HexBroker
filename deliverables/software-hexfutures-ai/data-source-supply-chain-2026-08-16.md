## 二、数据源供应链设计

```
┌─ 历史批量链路（回测/研究，2018-至今）─────────────────────────────┐
│   主源：MCP 腾讯自选股（westock）  —— 全历史、已验证               │
│   备源：sina 公开接口              —— 全历史、与本基准 100% 一致 ✅  │
│   校验：两源独立实现交叉验证（本报告已证明一致）                     │
│   受限：pytdx（代码就绪，网络环境不可达，恢复网络即可启用）           │
└──────────────────────────────────────────────────────────────┘

┌─ 实时/盘中快照链路（监控/盘中决策）──────────────────────────────┐
│   主源：MCP 腾讯自选股（westock，实时行情）                       │
│   备源：sina 实时接口（近期 ~130 根窗口，够快照比对用）            │
│   校验：实时快照末值 ↔ K 线末值比对（free.yaml verification 段）   │
└──────────────────────────────────────────────────────────────┘
```

### Failover 优先级（configs/data/free.yaml 更新）

| 用途 | 优先级顺序 | 理由 |
|---|---|---|
| 历史批量 | **sina → pytdx** | sina 已验证可用且全历史；pytdx 排后（网络不可达时快速跳过，避免 3 服务器超时等待拖慢主链路） |
| 实时快照 | westock → sina | MCP 为实时主源，sina 兜底 |

> 变更：`source_priority: [pytdx, sina]` → `[sina, pytdx]`（原 akshare_fundamentals 未装依赖，移出主链）。

## 三、工程要点

1. **sina 适配器**：`_fetch_one` 全量拉取 + `_clip_range` 裁剪，天然支持任意历史区间；含限频保护（0.3s/请求）与 OHLC 修复（`_repair_ohlc`，废 bar 丢弃/包络修复）；
2. **对比脚本可复用**：`scripts/compare_data_sources.py`（--start/--end/--symbols 参数化），新接入数据源时可扩 `SOURCE_MAP` + 适配器；
3. **数据可信度**：sina 与 MCP 两套独立实现 100% 一致，交叉验证通过——研究数据基准（data/raw/processed）可信；
4. **已知限制**：pytdx 服务器超时时间较长（3 服务器依次尝试），网络恢复前主链路不要放 pytdx 优先。

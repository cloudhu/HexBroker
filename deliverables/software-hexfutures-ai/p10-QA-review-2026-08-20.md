## 4. 关键裁决

### 4.1 ComboConfig 是否更新（A0 / A5 / 维持 A10）？
**QA 专业意见：维持 A10/B90 默认，不建议更新。** 理由：
1. **OOS 增量小**：A0 相对 A10 仅 +0.011 Sharpe / +2.35pp；A5 仅 +0.007 / +1.17pp。
2. **全样本反降**：A0 全样本 Sharpe 0.972 vs A10 1.023（-5%）；A0 的 OOS 优势建立在引擎 A OOS IC 为负的先验上，而引擎 A 全样本有真实贡献。
3. **OOS MaxDD 更深**：A0 -6.67% vs A10 -6.13%（引擎 A 提供回撤缓冲/分散化）。
4. **边界选择风险**：A0 是测试下界（非网格内部最优），单调趋势下"下界最优"是结构性结论而非新信息——纯按 OOS 选 A0 有 overfit OOS 窗口嫌疑；这与 P9"因稳健性/先验选 A10 而非 OOS 极值"的先例一致。
5. **若主理人倾向折中**：A5/B95 优于 A0（保留 5% 引擎 A 分散化、全样本 0.998 更接近、MaxDD -6.40% 居中），但仍建议保持 A10 以维持 P9 已验证基线。

### 4.2 `load_config()` 无参语义
**保持现状（无参不加载 base.yaml）——工程师实现与项目现有语义一致，不修正。** 依据：
- `load_config(path=None)` 自项目初始化（2c8a40b）起就是"无参 = 空 yaml 合并代码默认"，无默认 yaml 路径；base.yaml 是 Hydra 式组合片段（experiment yaml 的 `defaults: [base,...]` 引用），运行时脚本（grep 全仓 40+ 处 `load_config()`）全部拿代码默认。
- 改成"无参=加载 base.yaml"会改变所有既有调用的行为（如 experiment 标签、潜在嵌套覆盖），风险大、收益小。
- **但由此引出 DISCREPANCY-1（见 §5）**：`_resolve_group_map/_resolve_group_cap` 的 docstring/测试暗示"无参调用自动应用 base.yaml"，实际不可达。

## 5. DISCREPANCY 说明

### DISCREPANCY-1（中度，设计/接线缺口，非回归）
**`_resolve_group_map/_resolve_group_cap` 的"读配置"分支在生产中不可达。** 两个函数在参数为 None 时调用 `load_config()`（**无参**），而无参配置永远返回 `group_map=None/group_cap=None`（base.yaml 不被加载）→ 分支永远走兜底（GROUPS_V2/不启用）。实测：
```
真实 _resolve_group_map(None) → i0 组 = ferrous_raw | rb0 组 = ferrous_steel   # 非 ferrous_all
真实 _resolve_group_cap(None) → None                                            # 非 0.5
```
**影响**：任何"无参调用 `engine_a_targets_cs(prices, TOP_K, 3)` 期望 base.yaml 自动生效"的部署**不会**得到 cap。base.yaml 的 group_cap=0.5/group_map 仅在调用方显式 `load_config("configs/base.yaml")` 并**显式传参**时才生效（P10 Stage 2 已示范，P9 亦一贯显式传参）。`p6_5_config_validate.py` [4b] 与 `test_engine_a_group_resolve.py` 通过 **mock load_config 返回已配置值**验证优先级——该场景真实 load_config() 无法产生，测试覆盖了"逻辑"但未覆盖"接线"。
**建议（三选一）**：
1. 将"显式传参"固化为部署标准并写入文档/函数 docstring（当前 p10 Stage 2 即范例）；
2. 给 `_resolve_*` 增加可选 `cfg` 参数（或读部署默认 yaml 路径），使"读配置"分支真正可命中 base.yaml；
3. 移除"读配置"分支，docstring 改为"None → 默认（GROUPS_V2/不启用）；部署启用需显式传参"，避免误导。
> 注：此缺口**不构成向后兼容破坏**（无参行为 = P9 基线不变），仅影响"base.yaml 自动启用"这一预期是否成立。由工程师按部署接线方式决定是否修正。

### DISCREPANCY-2（低，非新增）
`load_config()` 无参 `experiment="demo"` vs base.yaml `experiment="e01_cu_daily"`——P10-1 之前已存在（base.yaml 自 init 就带 experiment 字段），仅标签差异，不影响回测行为。

### DISCREPANCY-3（低，信息项）
`scripts/p7_engineA_fix.py` 的 `build_engineA_targets` 是独立诊断助手（镜像口径、无 group_cap/group_map 参数），不属生产双入口，未受 P10-1 影响（也不应受影响）。生产入口统一在 `engine_a_targets_cs` → `engine_a_selection`。

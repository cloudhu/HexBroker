## 三、P0 缺陷详解

### P0-1 冷却指纹永不失效（今日主停摆原因）

**代码**（`hexbroker/paper/scheduler.py`）
- L124：`self._last_sig_fp: dict[str, tuple[float, float, str]] = {}` —— 仅内存，**不持久化**
- L293-306：无持仓 + 意图开仓 + 指纹相同 → `target_position = 0`，`reason = "signal_cooldown"`
- L356-362：**仅在实际开仓时**写入指纹；**平仓不清除、无 TTL**

**机理**：指纹 = (p_up, exp_ret, source)，而主源是**日线模型**输出 —— 一天之内恒定（今日 p_up 从 09:07 到 11:29 恒为 0.8667）。于是：

```
09:05:57 开仓 → 写入指纹 (0.8667, 0.4480, engine_a)
09:06:58 平仓 → 指纹仍在（未清除）
09:07 起    → 无持仓 + 意图开仓 + 指纹相同 → 永久拦截
```

**结果**：当日 09:07 之后 rb0 再无成交，127 次轮询全部空转。冷却的设计意图是"消除 60s 开-平-开-平 循环"，实际效果是"**每品种每天最多开 1 次仓，平仓后当天永不再开**"——属过度矫正。

**修法（三选一或组合）**
1. 平仓时清除该品种指纹，并写入冷却到期时间（TTL，建议 15–30 min）；
2. 指纹增加**信号日 ts**维度：信号日变化即视为新信号，立即放行；
3. 指纹持久化进 `account.json`，跨重启保持一致（当前三窗口架构 08:55/13:25/20:55 重启即丢）。

#### ✅ 状态：已于 2026-09-01 13:20 实现并交付（待下一个交易日生效）

### 🆕 P0-5 S2/S5 缺开仓保护门 → 开仓后下一 tick 被秒平（**今日真实事故，已修**）

**事故时序**（`data/paper/trades.log`，今日共 **4 次**开→秒平循环）：

| 开仓 | 平仓 | 间隔 | 净亏 |

**根因**：

1. 生产 bars 来自 sina 日线且**不含当日**（末根恒为上一交易日）→
   `recent_returns[-1]` 语义是「**昨日已实现收益**」而非「当前波动」。
2. 2026-08-31 rb0 涨 **+2.731%**，z = **3.6411 > 3.0** → S5 判定成立。
3. 该值**一整天不变**（日线 bars 全天恒定）→ 一旦成立，每个 tick 重复成立。
4. **S5 无最小持仓保护**（S1 有 `s1_min_bars`，S5 仅判 `len(recent_returns) >= 5`）
   → 开仓后**下一个 tick** 即被平仓。
5. 空仓时 `if state.position == 0: return []` 短路 → 开仓那一 tick 安全，
   **恰在下一 tick 爆发**，与 60s 间隔完全吻合。

**为何不是"换用当日收益"**：实测两种口径触发率 —— 滞后口径 **0.70%**，
改当日收益口径 **2.62%**（因 r 不再落入 mu/sd 窗口，z 失去自抑制而失去上界）。
且回测口径（`rl/futures_env._market_context` 的 `self._rets[lo:i+1]`）**含当前 bar**，
与现状**分布一致、仅平移一根**。故**不做口径替换**——那会破坏回测对齐且显著更激进。

**修法（已实现）**：给 S2/S5 补上 S1 已有的开仓保护门，并引入统一门
`sell_min_bars`（缺省 2），支持逐信号覆写 `sell_sN_min_bars`。

### P0-4 `_size_qty` 突破风控仓位上限

**复现输出**（`diag_0901_decision.py`）

```
① 09:05:57 开仓前  equity=94967.46 drawdown=0.0503
  → intent=0.3000 | target_position=0.150000 | reason=rl_intent
  → _size_qty 明细: raw=0.445438 手 → max(1,int(raw))=1 手  [风控批准 0.4454 手]
     ⚠️ 仓位放大 2.24 倍（风控意图 0.4454 手 → 实开 1 手）
```

**代码**（`planner.py` L100-104）
```python
raw  = abs(pos_pct) * equity / (price * multiplier)
lots = max(1, int(raw))          # ← raw=0.445 → int→0 → max(1,0)=1
```

**机理**：账户处于 **R1 回撤恢复态**（drawdown 5.03% > 5%，scalar=0.5），风控把意图从 30% 削到 **15% 权益**；但 `max(1, ...)` 把 0.4454 手强抬到 1 手 → 实际名义敞口 31,980 / 权益 94,967 = **33.7%**，是风控批准的 **2.24 倍**。

**修法**：`raw < 1` 时应**不开仓**（`return 0.0`），由预算防线（`budget_ratio`）决定是否允许"1 手起步"；绝不能让取整逻辑越过风控上限。若坚持"至少 1 手"，须改为**先校验 1 手是否满足风控上限，不满足则拒单**。

## 二、级联语义取证（signals.py L464-504）

`latest_signal` 的四段逻辑：

```python
# ① 主源新鲜 → 直接用主源（健康态永远走这里）
if fd0 <= self._freshness_threshold:
    return self._build_frame(symbol, row0, i0, fd0)

# ② 主源过期 → 仅当兜底源信号 ts 严格晚于主源才被采用
for i, row, fd in rows[1:]:
    if pd.Timestamp(row["ts"]) > ts0:   # ← v8 永远过不了这道门
        ...

# ③ 兜底也无效 → 返回主源过期信号（is_effective=False，保守拦截）
return self._build_frame(symbol, row0, i0, fd0)
```

**推演所有场景**（阈值=0，tail_ext 为主源、v8 为兜底）：

| 场景 | tail_ext 状态 | v8 能否被采用 | 实际结果 |
|------|--------------|--------------|---------|
| 健康（每日刷新） | fd=0 | 否（fd0≤0 直接 return） | 主源信号，正常 |
| tail_ext 停更 N≥1 交易日 | fd=N 过期 | **否**（v8 ts 更旧） | 主源过期信号 → `is_effective=False` → 保守拦截 + 技术兜底接手 |
| 某 symbol 在 tail_ext 无信号 | — | 否（实测品种全覆盖，起点均 2019-04-01） | 不存在的场景 |
| v8 文件损坏/被清理 | — | — | ⛔ **启动期 FileNotFoundError 致命**（L454-455），引擎起不来 |

**关键结论**：上表第 2、3 行证明 v8 在位与不在位，**生产行为完全相同**；而第 4 行证明 v8 在位反而多一个致命单点。

机制本身（`cache_paths` 级联 + fbN 兜底）有测试覆盖（`test_paper_signals.py` L72-81、`test_signal_freshness.py:351`），**不是缺陷** —— 缺陷的是这套机制被套在了一个「永不比主源新」的源上。测试保留，与配置解耦。

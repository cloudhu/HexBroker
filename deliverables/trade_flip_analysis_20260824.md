# 交易系统「做多后很快平仓」根因分析（2026-08-24）

> 数据源：`data/paper/trades.log`（2026-08-24 上午 256 笔唯一成交）+ 源码链路
> （scheduler → risk_gate → risk/manager → risk/sell_engine → planner → broker）+ 信号缓存。

## 一、现象

上午 256 笔成交呈现**每 60 秒一轮的开→平→开→平循环**（poll 间隔 60s）：

| 时刻 | rb0 | ag0 |
|---|---|---|
| 09:05:07 | **开多** 3038（stop 2917.89 / tp 3215.66） | **开空** 16895.99 |
| 09:06:09 | **平多** 3036（今平） | **平空** 16896.01（今平） |
| 09:07:10 | **开多** 3038 | **开空** 16895.99 |
| 09:08:11 | **平多** 3036（今平） | **平空** 16896.01（今平） |
| … | 循环至 11:29（rb0 64 开×64 平、ag0 64 开×64 平） | |

即：**rb0 反复"做多→60 秒后平多→再做多"，ag0 反复"做空→60 秒后平空"**，方向自始至终不变。

## 二、排除项（不是这些原因）

| 可能原因 | 判定 | 证据 |
|---|---|---|
| 止损触发 | ❌ | rb0 开多 3038、平仓 3036，止损 2917.89 远未触及；ag0 同理 |
| 止盈触发 | ❌ | 止盈 3215.66 远未触及；刚开仓 1 分钟浮盈 <1%，S3 需 ≥10% |
| 时间止损 S4 | ❌ | 需 `bars_in_position ≥ 20`，刚开仓仅 1 根 |
| 信号方向翻转 | ❌ | rb0 p_up=0.733、ag0 p_up=0.267 **全程恒定**（engine_a，新鲜度 1 天） |
| 波动异常 S5 | ❌ | 需 z>3 极端波动，价格仅 ±2 点微幅往返 |

## 三、根因：S1「趋势破坏」在开仓初期被均线穿越反复触发

**决策链**（`scheduler._process_symbol`）：

```
信号 p_up(恒定) → RiskGate._intent → 意图仓位 ±0.30(方向恒定)
  → RiskManager.evaluate：target = intent×scalar
  → detect_sell_signals（S1–S5）命中 → target=0 + liquidate=True  → 平仓
  → 未命中 → target=±0.30 → 开仓
```

**S1 规则**（`risk/sell_engine.py:42-46`）——唯一在开仓初期可能命中的信号：

```
多头持仓且 current_price < ma_price(日线 MA20)  → S1 触发 → 平多
空头持仓且 current_price > ma_price(日线 MA20)  → S1 触发 → 平空
```

**关键事实**：`ma_price = close.rolling(20).mean()`（日线，当日恒定）；而成交价在
**固定两值之间交替**（rb0 3038↔3036、ag0 16895.99↔16896.01——历史价格体系的微幅抖动）。

→ 当 MA20 恰好落在两值之间（rb0 ≈3037）时：

```
开仓轮：price=3038 > MA20 → S1 不触发 → 开多
平仓轮：price=3036 < MA20 → S1 触发  → 平多（liquidate）
再开轮：price=3038 > MA20 → S1 解除 → 再开多 …… 循环
```

**这就是「做多后 60 秒即平仓」的直接机制**：价格贴着日线 MA20 来回穿越，
S1 在相邻轮次反复触发/解除，导致开-平-开-平循环。ag0 空头同理（16895.99 < MA < 16896.01）。

## 四、附带发现的两个 Bug

### Bug A：止损价跨品种串扰（`RiskManager._prev_stop` 共享）

T000003（ag0 平仓）事件的 `stop=2917.89`——**这是 rb0 的止损价**（rb0 开多 3038 的 ATR×2.5 止损）。

根因：`RiskGate` 的 `self._manager`（RiskManager）被所有品种共用，而
`manager.evaluate` 里 `self._prev_stop`（trailing_stop 的"止损只上移不下移"记忆）是
**单一实例变量**——ag0 与 rb0 交替 evaluate 时互相污染上一品种的止损记忆。
影响：平仓事件日志的 stop 字段错乱；若持仓交替，真实止损计算也可能被串扰。

### Bug B：`is_open` 被序列化为字符串 `"False"`

T000003/4 等事件的 `is_open` 是**字符串 `"False"`**（非布尔），truthy 导致
按 `if is_open:` 判断的解析器误判为"开仓"（本次分析即踩坑）。
根因：`log_structured` 序列化路径 `default=str` 将 bool 字符串化（历史已知瑕疵）。
`trade_intent` 已做兼容，但下游解析需统一。

## 五、修复建议（按优先级）

1. **P0｜S1 开仓缓冲**：`bars_in_position < N`（如 2~3 根）时禁用 S1，避免开仓初期被
   均线穿越"秒平"；或 S1 增加"连续 2 个 tick 均低于均线"确认（`sell_engine.py`）。
2. **P0｜S1 均线口径**：MA20 固定日线在盘中不更新，穿越判定过于敏感；可改为
   日线 MA + 盘中价连续偏离确认，或对 MA 穿越设带宽（±0.1×ATR）死区。
3. **P1｜`_prev_stop` 按 symbol 隔离**：`RiskManager` 的 ratchet/止损记忆改为
   `dict[symbol, ...]`（`manager.py`），消除品种间串扰。
4. **P2｜`is_open` 序列化统一 bool**：`log_structured` 对 bool 字段不套 `str()`。

## 六、结论

- 做多后很快平仓 **不是信号错误、不是止损/止盈误触**，而是 **S1 趋势破坏规则
  在"价格贴近日线 MA20 往返穿越"场景下，开仓后下一轮（60s）即被触发平仓**，
  并在均线穿越反复出现时形成开-平循环。
- 该行为放大了交易成本（256 笔中 128 笔为平仓，手续费 ¥2724.54 占净亏 68%），
  且暴露 S1 对"开仓初期 + 均线贴线"场景缺乏保护。
- 修复建议见上；实施后应复跑 8/24 上午场景做回归验证（开-平循环应显著减少）。

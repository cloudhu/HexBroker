## 1. 任务 1：p37 失效根因（代码行号级）

### 1.1 「raw_close 是否是真名义价」的判定条件是什么

**没有语义判定，只有一个幂等短路。**

`scripts/p37_raw_close_backfill.py`：
- `p37:178-179` 调 `enrich_raw_close(df, sym, fetcher=fetcher, min_coverage=...)`
- `p37:182-183`：
  ```python
  changed = int((df[CHANGED_COL].to_numpy() != new_df[CHANGED_COL].to_numpy()).sum())
  ```
- `p37:189-191`：`if changed == 0: print("[SKIP] ... raw_close 已是真名义价 ..."); continue`

所以判定条件 = **「备源返回值与现有 `raw_close` 逐行全等」**。代码从未检查 `raw_close` 是否等于 `adj_close`、是否偏离复权因子、是否是名义价语义 —— "已是真名义价" 是一句**误导性的推断**，不是检测结论。

### 1.2 `enrich_raw_close` 全文行为（`scripts/p6_4_fill_gaps.py:514-577`）

- `p6_4:545` 拉备源：`pulls = fetcher.fetch_raw([sym0], start, end)`（默认 `BackupRawFetcher(save=False)`，优先级 `sina → akshare → czce`，见 `hexbroker/data/backup.py:34`）
- `p6_4:556-558` 取 `pull.close` 归一化为 `nom`
- `p6_4:559` 按日期对齐 `aligned = df["datetime"].map(nom)`
- `p6_4:560-564` 覆盖率门禁（`coverage < min_coverage` 则原样返回并留归因）
- `p6_4:566-569` **唯一写入动作**：
  ```python
  out = df.copy()
  out["raw_close"] = aligned.astype(float).fillna(df["raw_close"]).to_numpy()
  ```
- `p6_4:566-577`：**全程不读取、不校验 `adj_close`**，也没有任何 "返回值是否为复权价" 的鉴别逻辑

即：`enrich_raw_close` 是一个**纯覆盖器**（把备源 close 灌进 `raw_close`），不具备"诊断"能力；诊断/短路完全由 p37 的 `changed == 0` 承担。

### 1.3 为什么 2018-2024 判成「几乎无需更新」

因为**这些分区的 `raw_close` 早就是 sina 名义价**，p37 拉的是**同一个 sina 备源、同一条序列** → 逐位相同 → `changed == 0` → SKIP。

实测（探针 4，全湖 18 品种 × 9 年，sina 新端点 vs 湖内值）：

| 品种/年 | raw_close == sina 占比 | adj_close == sina 占比 |
|---|---|---|
| ag0 2018 | **100.0%** | **100.0%** |
| ag0 2019~2024 | 98.5%~100.0% | 81.5%~96.7% |
| au0 2018 | **100.0%** | **100.0%** |
| au0 2019~2024 | 98.5%~100.0% | 75.6%~89.7% |
| m0 2018 | **100.0%** | **100.0%** |
| m0 2019~2024 | 98.5%~100.0% | 88.5%~96.3% |

（完整表见 `C:\Users\Administrator\AppData\Local\Temp\caliber_forensics\probe4_lake_scan.csv`）

主理人的假说「**sina 自证清白**」**成立**，但机制是「**同源**」（两边都是 sina 名义价），不是「同为后复权口径」。

### 1.4 为什么 2025/2026 反而 100% 需要更新

这两年 `adj_close` 是 pandadata 后复权（未被覆盖），`raw_close` 是 parse 阶段的 adj 复制品（`p6_4:482-483`：`raw_close = close*scale` / `adj_close = close*scale`），与 sina 名义价不同 → 全行改写。

**p37 在 2025/2026 上的修复是正确的**，在 2018-2024 上无事可做也是"正确"的 —— 它只是修错了列。

### 1.5 根因一句话

> `p37:189-191` 用"备源值与现有 `raw_close` 是否逐行相同"冒充"raw_close 是否是真名义价"的语义判定；而 `enrich_raw_close`（`p6_4:566-569`）只覆盖 `raw_close`、从不校验 `adj_close`，因此当 `raw_close` 已被同一备源写过时，p37 必然自证清白、静默跳过，且**无法发现真正坏掉的 `adj_close`**。

## 4. 任务 3：方案评估与推荐

### 方案 1：修 p37 / `enrich_raw_close` 的判定逻辑后重跑 —— ❌ 无效（对本案）

- `raw_close` 在 2018-2024 上**本来就正确**（与 sina 名义价 98.5%~100% 相同，且 sina 名义价已被 pandadata 单合约行情逐位交叉验证）。改判定逻辑只会让它多改 0~1.5% 的行（见下"风险"），**永远修不了 `adj_close`**。
- `enrich_raw_close` 按契约只负责 `raw_close`（`p6_4:517-533` 的 docstring 明确写了这一点），让它去修 `adj_close` 是越界。
- **但有一件事值得改**：把 `p37:190` 的措辞从「raw_close 已是真名义价」改成「备源值与现有 raw_close 逐行相同（幂等跳过）」，并新增一条**污染告警**：若 `adj_close` 与备源名义价的逐位相同率 > 50%，说明 `adj_close` 已退化为名义价，必须大声报出（这正是本案的漏检点）。

### 方案 3：用 2025-2026 的真值 k 反推历史 —— ❌ 明确否定（比主理人判断的更不可行）

两条独立论证：

1. **k 逐年漂移，不可外推**。真 k（pandadata close_pcr / 名义价）实测：ag0 2018-06 = 0.7986 → 2019-03 = 0.7916 → 2019-12 = 0.7736 → 2024-06 = 0.6931 → 2025-01 = 0.6869 → 2025-11 = 0.6768；对照组 rb0 九年从 0.763 漂到 1.20。用某一年 k 反推必然引入 20%~70% 量级的水平误差。
2. **2025/2026 的 k 本身就不是真值 k**（见 §3）：与 pandadata 锚点差常数 ag0 ×1.45052 / au0 ×1.25965 / m0 ×0.31683。拿它当基准会把这个常数误差原封不动带进 2018-2024。

### 方案 4（推荐）：p11 真值重建，三品种 × **9 年** = 27 个分区

`scripts/p11_truth_rebuild.py` 已在 rb0/2020、rb0/2023、cu0/2023 上跑通（pandadata close_pcr 全年真值 + 整分区替换 + 前置全覆盖预检 + 边界连续性校验），是现成且已验证的路径。

执行要点：

1. **范围必须是 3 品种 × 9 年 = 27 个分区，不是 21 个**。
   - 21 个（2018-2024）是 `adj_close` 被降级为名义价的分区；
   - 2025/2026 另 6 个也必须重建，否则重建后的 2024 与未重建的 2025 之间会出现 **+45%（ag0）/ +26%（au0）/ −68%（m0）的假跳变**，比现状更糟。
2. **顺序**：先建 2025、2026，再建 2018→2024（倒序），让每次边界校验（`p11:190-205`，>10% 跳变即报警）都能对上已重建的一侧。
3. **raw_close 自动处理**：`p11:124` 会调 `enrich_raw_close` 用 sina 名义价回填 `raw_close`。对 2018-2024，回填值与现值 98.5%~100% 相同，等于幂等；对 2025/2026 与现状一致。
4. **前置预检**：`p11:129-152` 要求真值日期**全覆盖**既有分区，否则 rc=1 零写盘。注意 ag0/2024 与 m0/2024 现只有 130~131 行（年度未写满），拉取区间要覆盖到 12-31。
5. **dry-run 先行**，核对每分区 "替换行数 == 既有行数"，再 `--apply`。

风险与注意事项：

- **pandadata 配额**：27 次全年拉取，需确认额度。
- **`--sym` 推导**：`p6_4.normalize_sym_arg` 从 `ag0/au0/m0` 推 underlying（`AG`/`AU`/`M`），建议首次 dry-run 时打印确认。
- **`raw_close` 残留坏 bar 不要用 p43 先修**：`p43_raw_close_spike_repair.py` 的 G4 门禁（`K_IDENTICAL_CAP=0.5`）与 `DEFAULT_DENY_SYMBOLS=("ag0","au0","m0")` 已冻结三品种 —— 这个冻结**现在是对的**（段内 k≡1 前提不成立）。等 adj 重建完成、k 不再恒为 1 后，G4 会自动解除，届时才可放行 p43。
- **不要假设 sina 全对**：湖内 `raw_close` 与 sina 新端点差异的 0.8%~1.5% 中，**部分是 sina 新端点的单日坏 bar，不是湖内错**。证据：2019-05-08 sina=3549，而当日全部 AG 合约收盘价落在 3606~3646 区间（湖内 3607 接近 AG2001 的 3606）；2019-11-13 sina=4123，同样落在合约价区间 4137~4201 之外。修复 `raw_close` 时应以 **pandadata 单合约名义价**（`get_future_daily`）为准，而非 sina。

## 5. 对主理人背景的四处更正

1. **「`adj_close` 是 pandadata 主源真值，可信」** —— 对三品种 2018-2024 **不成立**。`adj_close` 就是 sina 名义价（探针 4：`adj_eq_sina_pct` 75.6%~100%），比 pandadata 真值高 25%~44%。
2. **「`raw_close` 被污染成 `adj_close` 的逐字复制品」** —— **因果倒置**。是 `adj_close` 被降级为名义价导致两列相等；`raw_close` 是三列里唯一与真名义价（pandadata 单合约价）吻合的。
3. **「2025/2026 的 k 中位数才是真值」** —— **部分错**。形状真、锚点假（ag0 ×1.45052 / au0 ×1.25965 / m0 ×0.31683）。因此"真值年"只有 6 个分区，而且也是坏的。
4. **「21 个分区被覆盖（2026-08-23 13:39:42）」** —— 数量吻合（3 品种 × 7 年 = 21），但**时间戳只能对上 3 个文件**：`ag0/2018`、`au0/2018`、`m0/2018`（mtime = 2026-08-23 13:39:42）。2019-2024 的 18 个文件 mtime 已被 2026-08-29 18:13（p37）与 20:01（p43）的整文件重写覆盖，**不能凭 mtime 归因**。这三品种 2019-2024 的污染时点需另查 2026-08-23~08-29 的拉取/切换日志；不影响本报告的修复结论。

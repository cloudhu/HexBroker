## 1. 产品目标

**一句话目标**：在**不触碰双闸门验收口径、防泄漏红线、315 项测试全绿**的前提下，把 HexBroker「研究 → 实盘」链路的可信度（撮合假设可解释、偏差可量化）、工程化防前视（策略层自检）、可复现性（四层版本对应）、统计显著性（绩效区间）补齐到工程级。

**关键成功指标（KPI，全部可度量）**：

| 维度 | KPI |
|---|---|
| P0-1 撮合可信度 | 撮合假设文档 ≥14 条，每条含默认值与影响方向（乐观/保守/中性）；`next_bar_execution` / `volume_cap` 双开关可用且**默认关闭**；报告输出双口径绩效对照（含 Δ%）；默认配置下历史绩效数值与改动前完全一致 |
| P0-2 前视自检 | 对注入的前视/递归缺陷样本检出率 100%；对现有策略/特征代码 **0 个未豁免误报**；CLI 接入 CI 与 pipeline 报告 |
| P0-3 四层版本化 | 100% 新数据批次生成 DataLake manifest；SignalStore 100% 记录四层指纹；同配置重跑指纹一致、改配置指纹必变（敏感性验证） |
| P0-4 Bootstrap 区间 | 报告输出 Sharpe / Calmar / MaxDD 的 block bootstrap 95% CI；固定 seed 可复现；模拟数据覆盖率验证 ≈95% |

## 2. 用户故事

### P0-1 撮合可信度加固

- 作为**研究员**，我希望撮合假设（成交时点、成交价、滑点、成交量约束）被显式文档化，以便理解每个绩效数字背后的假设，并判断其系统性乐观/保守方向。
- 作为**研究员**，我希望通过 `next_bar_execution` / `volume_cap` 开关一键切换保守撮合口径，以便量化「同 bar 成交」造成的绩效偏差。
- 作为 **QA / 审计者**，我希望报告自动输出「同 bar vs next_bar」双口径对照，以便在**不改动生产基线口径**的前提下评估全部历史绩效的可信度。

### P0-2 前视/递归依赖自检工具

- 作为**研究员**，我希望在提交策略前运行 `lookahead-analysis` CLI，以便在实验早期发现特征/策略代码中的未来函数。
- 作为 **QA**，我希望 `recursive-analysis` 能检测特征递归依赖（如特征依赖自身未来值、跨 bar 回环），以便把「防泄漏」从训练层红线扩展到策略层工程化自检。
- 作为 **CI 维护者**，我希望自检工具接入 pytest / pipeline，以便每次回归自动拦截前视缺陷。

### P0-3 数据-信号-模型四层版本化

- 作为**研究员**，我希望每次实验报告携带四层指纹（数据 / 特征 / 模型 / 参数），以便不同轮次实验可直接对比、可复现，不再依赖手工文档回忆口径。
- 作为**主理人 / 审计者**，我希望 DataLake manifest 记录数据版本与口径常量（如 `RAW_SCALE_FIX`），以便 40+ 轮实验史中的「v2/v8 缓存、buggy/fixed broker」类口径混淆可系统追溯。
- 作为**工程师**，我希望 SignalStore 在写入/读取时自动校验四层指纹一致性，以便从机制上防止版本错配的缓存混用。

### P0-4 Bootstrap 绩效区间

- 作为**研究员**，我希望报告同时输出「点估计 + 95% CI」，以便判断两个策略的绩效差异是否统计显著。
- 作为**主理人**，我希望双闸门判定附带区间支撑，以便过线判定不依赖单一点估计。

## 3. 需求池（P0 × 4）

> 通用红线约束（每项验收均须满足）：
> - **不触碰双闸门口径**：方向准确率≥54%（闸门1）/ OOS 计入成本 + PBO<0.5 + DSR>0（闸门2）判定逻辑与判定结果不变；
> - **不触碰防泄漏红线**：SignalStore 只落 OOS 信号、RL 环境只读、L1-L9 防泄漏机制不变；
> - **315 项测试全绿底线**：改动后既有 315 项测试必须全绿，新增功能须补对应测试。

### P0-1 撮合可信度加固

| 项 | 内容 |
|---|---|
| **需求描述** | 将现有撮合行为（固定 `slippage_ticks=1.0`、同 bar 成交、无成交量约束、涨跌停拦截 P8）显式化为撮合假设清单（借鉴 freqtrade 14 条撮合假设 + backtrader 撮合细节）；新增 `next_bar_execution` 与 `volume_cap` 可配置开关；回测报告输出「当前假设 vs 保守假设」双口径绩效对照，量化同 bar 成交偏差。 |
| **功能清单** | F1.1 撮合假设文档：新增 docs 章节，≥14 条假设，每条含【内容 / 默认值 / 影响方向（乐观·保守·中性）/ 对应代码位置】，覆盖：成交时点、成交价格、滑点、成交量/流动性、部分成交/整单拒绝、跳空、手续费/保证金、涨跌停、平今判定、复权口径、数据对齐、订单类型、资金约束、跨 bar 依赖。<br>F1.2 `next_bar_execution` 开关：backtest 配置项；开启后成交价取下一 bar（具体口径见待确认 Q1），**默认关闭**。<br>F1.3 `volume_cap` 开关：成交量约束（下单量 ≤ bar 成交量 × 比例），超量处理语义见待确认 Q4，默认关闭/宽松。<br>F1.4 双口径对照报告：报告自动输出「同 bar vs next_bar」两组绩效（Sharpe / Calmar / MaxDD / 方向准确率）及 Δ%。<br>F1.5 兼容性：默认参数下与现有生产基线口径 100% 一致。 |
| **验收标准** | A1.1 撮合假设文档存在且 ≥14 条，每条含默认值与影响方向（文档结构检查测试）。<br>A1.2 默认配置（`next_bar_execution=False, volume_cap=None`）下，现有回测绩效与改动前**数值完全一致**（<1e-12）——证明未触碰生产基线口径。<br>A1.3 `next_bar_execution=True` 可运行，报告输出双口径对照表（含 Δ%），双口径差异被显式量化。<br>A1.4 新增测试：同 bar vs next_bar 对照、volume_cap 部分成交/拒绝语义；既有 315 项测试全绿（总数 >315）。<br>A1.5 改动仅限 backtest 撮合层，SignalStore / OOS 物理隔离逻辑零改动——防泄漏红线不变。 |
| **借鉴对象** | freqtrade（14 条撮合假设）、backtrader（下一根 K 线成交 / 跳空 / 成交量封顶） |

### P0-2 前视/递归依赖自检工具

| 项 | 内容 |
|---|---|
| **需求描述** | 借鉴 freqtrade `lookahead-analysis` / `recursive-analysis`，为特征/策略 target 生成链提供 DAG 依赖分析 CLI：检测「同一 bar 内用收盘价决定成交」等未来函数模式与跨 bar 递归依赖，并接入 pytest 与 pipeline 报告。 |
| **功能清单** | F2.1 `lookahead-analysis` CLI：对特征计算/信号生成链做依赖分析，检出同一 bar 内使用未来信息（如 bar t 收盘价参与 bar t 成交决策）的模式。<br>F2.2 `recursive-analysis` CLI：检测特征递归依赖（A→B→A 回环、特征依赖自身未来值、`shift` 负向/`center` 滚动等危险原语）。<br>F2.3 DAG 依赖图：输出 target 生成链依赖 DAG（节点=特征/信号，边=依赖关系），标注可疑边与证据。<br>F2.4 接入 CI 与 pipeline：自检发现缺陷时非零退出 / 报告标注 FAIL。<br>F2.5 白名单/豁免机制：对已知安全模式（rolling/expanding z-score、外盘 `reindex→asof`、跨品种锁列）提供显式豁免，避免误报噪声。 |
| **验收标准** | A2.1 提供 CLI（如 `python -m hexbroker.tools.lookahead_analysis`）；对测试夹具注入的已知前视缺陷样本**检出率 100%**。<br>A2.2 对现有策略/特征代码运行，**0 个未豁免误报**（误报均可用白名单显式豁免）。<br>A2.3 `recursive-analysis` 能检出注入的递归依赖样本（A→B→A 回环）。<br>A2.4 工具接入 CI：缺陷存在时 CI 失败；既有 315 项测试全绿（新增测试）。<br>A2.5 工具为**只读分析**，不修改任何生产代码行为——防泄漏红线与生产基线不变。 |
| **借鉴对象** | freqtrade（lookahead-analysis / recursive-analysis） |

### P0-3 数据-信号-模型四层版本化

| 项 | 内容 |
|---|---|
| **需求描述** | 借鉴 qlib recorder / zipline bundle，为 DataLake 增加 manifest（数据版本 / 拉取时间 / 口径常量 / 指纹），为 SignalStore 增加「数据-特征-模型-参数」四层指纹列，报告统一输出四层指纹，根治 40+ 轮实验口径混淆（v2/v8 缓存、buggy/fixed broker、RAW_SCALE_FIX）。四层映射：**数据 Data**（DataLake manifest）→ **特征/信号 Feature-Signal**（特征管道配置指纹 + SignalStore 分片）→ **模型 Model**（model_id/train_end + 模型配置指纹）→ **参数 Parameter**（超参/训练参数哈希）。 |
| **功能清单** | F3.1 DataLake manifest：raw/interim/processed 每层保存 manifest（数据版本号、拉取时间、来源、口径常量如 `RAW_SCALE_FIX`、内容指纹），已有数据提供回填迁移脚本。<br>F3.2 SignalStore 四层指纹：在 `model_id/train_end` 分片基础上新增 `data_version / feature_version / model_version / param_hash` 四列。<br>F3.3 指纹计算：数据内容哈希、特征管道配置哈希（`FeaturePipeline` 配置序列化）、模型配置哈希、参数哈希。<br>F3.4 报告输出：回测/实验报告统一输出四层指纹块（含 config 版本）。<br>F3.5 一致性校验：SignalStore 写入/读取时校验四层指纹，不一致告警/拒绝（可配置）。 |
| **验收标准** | A3.1 每次数据保存自动生成 manifest（含指纹与口径常量）；存量数据可一键回填（迁移脚本测试）。<br>A3.2 SignalStore 记录含四层指纹字段，写入自动计算、读取可校验。<br>A3.3 同一配置重跑实验，四层指纹**完全一致**（可复现性测试）。<br>A3.4 修改任一配置（特征集 / 模型 / 参数）后指纹**必然变化**（敏感性测试）。<br>A3.5 报告输出含四层指纹块；既有 315 项测试全绿（新增测试）；不改信号语义——防泄漏红线与双闸门口径不变。 |

## 4. 优先级与依赖关系

- **优先级**：四项均为 **P0**，同批立项（主理人裁决）。
- **依赖关系**：**无硬依赖**，四项模块边界独立，可并行开发：
  - P0-1（backtest 撮合层）与 P0-2（feature/strategy 静态分析）共享 backtest/feature 代码域，但改动互不阻塞；
  - P0-3（元数据/版本层）与 P0-4（evaluation 统计层）均落在报告输出链路，存在**软协同**：建议 P0-3 指纹先入报告，P0-4 报告块可复用同一报告框架；
  - P0-4 依赖现有 DSR/PBO 点估计作为对照，属只读复用，无改动冲突。
- **建议实施顺序**：P0-1 / P0-2 / P0-3 并行优先（高收益低成本）→ P0-4（成本极低）随后接入报告；若容量受限，按 P0-1 → P0-3 → P0-2 → P0-4 排期，均不阻塞彼此。
- **共享约束**：四项均遵守「不触碰双闸门口径 / 防泄漏红线 / 315 测试全绿」铁律（见 §3 顶部）。

## 5. 待确认问题

1. **next_bar_execution 成交价口径**：开启后成交价取「下一 bar 开盘价」还是「下一 bar 收盘价 ± 滑点」？两者对偏差量化影响不同（freqtrade 默认 next bar open），需业务侧确认以固定默认值。
2. **双口径对照的输出位置**：是否作为生产报告（p23 / QA 消费）的默认输出？若默认输出，是否与既有报告格式/消费方存在兼容问题；或仅作为研究期开关？
3. **四层指纹的存储格式**：SignalStore 采用「Parquet 补列（schema 变更）」还是「独立 sidecar manifest（如 JSON）」？Parquet schema 变更对历史数据读取是否需向后兼容策略？
4. **volume_cap 超量处理语义**：超量部分按「部分成交（按比例）」还是「整单拒绝」？默认成交量比例阈值取多少（考虑 18 品种日频流动性差异）？
5. **block bootstrap 参数默认值**：block 长度（建议 20）与重采样次数（建议 1000/2000）是否可接受；是否需要按品种/策略维度分组 bootstrap 以刻画截面差异？

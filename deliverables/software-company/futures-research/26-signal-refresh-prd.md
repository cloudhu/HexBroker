# B+C 防再发批次 · PM 增量 PRD

> 触发：2026-08-28「交易系统不再交易」根因分析（`deliverables/trading_stall_analysis_20260828.md`）
> 目标：把"漏跑刷新 → 静默停摆"变成**不可能发生**（B）或**显性可见**（C）

## 1. 需求池

- **B1 启动期硬告警**：启动自检阶段探测信号缓存新鲜度（fd），fd>阈值 → 打印**醒目横幅**（含陈旧文件名/最新时间/fd/修复命令）。
- **B2 可选自动刷新**：配置 `signal_refresh.auto_enabled`（**默认 false**）开启后，启动期自动跑 `scripts/p22_tail_ext.py --skip-eval`；超时/失败降级为告警，**绝不阻断启动**。
- **C1 横幅可观测**：同上横幅（让"系统开着但不交易"在启动瞬间被看见）。
- **C2 0 开仓显性汇总**：当日累计各拦截原因次数；若当日 0 成交 → 输出 `[统计] 今日开仓 0 笔，未开仓原因分布：no_intent=N、…`（带"主因通常为主源信号过期"提示），去重防刷屏。

## 2. 验收口径

1. **默认零行为变更**：`auto_enabled=false` 时只告警不动作；无 stale 时不输出横幅。
2. **fail-safe**：探测/刷新/汇总任一异常 → 隔离并打印，**不阻断启动、不影响 tick**。
3. 横幅必须含：⛔ 不会开仓 + 陈旧文件名 + fd + 修复命令。
4. 0 开仓汇总：仅在当日无成交时输出，同指纹去重一次。
5. 真实配置断言锁定 `auto_enabled=false` 与 `threshold=0`。

## 3. 开放问题（裁决）

- **Q1** 是否默认自动刷新？→ **否**（刷新会拉取外部数据并重写缓存，属生产数据操作，需人工确认）。
- **Q2** 陈旧是否阻断启动？→ **否**（fail-safe：横幅告警，仍启动；用户可自行决定是否刷新后重启）。
- **Q3** 阈值口径？→ 与 P0-3 一致 **fd>0 即陈旧**（可配置）。
- **Q4** 0 开仓汇总频率？→ 随快照节奏（约 300s），去重后仅状态变化时输出。
- **Q5** 是否改门禁阈值 0→1？→ **否**（状态翻转，须 walk-forward QA；本批次不触碰）。

## 4. 批次

批次一：B1/B2/C1（模块 + 配置 + 启动接线）；批次二：C2（scheduler 原因累计 + 汇总）+ 测试 + 回归。

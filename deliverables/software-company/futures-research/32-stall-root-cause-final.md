### 证据 3：日盘 fd=1 是**设计预期**，不是故障

两条刷新自动化的提示词原文（工程侧早已写明）：

- 日盘（08:00）任务：「日盘 08:45 运行时，当日日线尚未收盘（15:00 才收），
  pandadata 返回的最新交易日为**上一交易日**，故融合后缓存延长到上一交易日，
  **fd 在 08:45→15:00 期间为 1（隔夜过期预期，非故障）**。
  **真正的 fd=0 由当晚 20:30 夜盘刷新任务（当日 15:00 后运行）达成**。」
- 夜盘（20:30）任务：「务必在**当日 15:00 收盘后、21:00 夜盘前**运行，
  方能将缓存延长到当日、取得 fd=0。」

今晨报告原文亦确认：「信号缓存延长至 2026-08-27（**fd=1，日盘 08:45 正确隔夜态**）」。

### 证据 5：阈值 0 与回测口径一致（A2 否决的硬依据）

`configs/base.yaml:48` → `next_bar_execution: false`，
`hexbroker/backtest/execution.py` 注明：**False = 同 bar close 成交（生产基线）**。

```
回测：信号(ts=T, 用 T 收盘价特征) → 在 T 收盘成交
实盘：T 15:00 收盘 → 出信号(ts=T) → T 21:00 夜盘 = 收盘后首个可执行时点
```

阈值 0 要求「信号日 = 执行日」，恰好等价于**收盘后首个可执行时点**。
**阈值 0 是正确设计，不是口径错误。**

## 二、根因终裁

```
08-27 20:30 夜盘刷新
   └─ Pandadata 网关 500009「单日总流量超限」（外部依赖，账户级配额）
        └─ 18/18 拉取失败 → 无 json 落盘
             └─ p6_4_apply_persisted_dir 安全跳过 → p22 未重建
                  └─ 缓存停在 08-26 → 夜盘 fd=1
                       └─ 主源过期 + P1-1/P1-2 技术兜底禁开 → 0 开仓

08-28 日盘
   └─ 早晨刷新 18/18 成功 → 缓存推进到 08-27
        └─ 日盘 date.today()=08-28, 信号 ts=08-27 → fd=1
             └─ 属【设计预期】（当日 15:00 才收盘，fd=0 只能由当晚 20:30 达成）
```

**结论：非代码缺陷、非运维漏跑、非口径错误。唯一根因 = 外部行情源账户级配额在 08-27 当日耗尽。**

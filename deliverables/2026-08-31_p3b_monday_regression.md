## 二、真正的 P0：P3-B 实现与其立项初衷相悖

### 2.1 立项初衷（一手证据，`.workbuddy/memory/2026-08-28.md` L172）

> 日频正确因果口径应为「T 收盘出信号 → T+1 执行」= `fd=1`；
> **P0-3 立项背景「周五信号周一用」在交易日意义上就是标准 T+1，与"陈旧"非同一概念。**

即：立项时已明确认定 **「周五信号周一用」不是陈旧，不该拦**。

### 2.2 实现结果（P3-B，commit `8a91230`）

度量改为**自然日差**、阈值 1。而周一 → 上一交易日周五，自然日差恒 = 3 > 1 → **拦截**。

**实现把立项时认为"不该拦"的场景拦掉了。**

### 2.3 我当时的推理错在哪

P3-B 的推理是：「`np.busday_count` 无法区分正常隔夜 / 跨周末 / 跨假期 → 改用自然日差」。

**这个推理方向反了。** 市场的日历是**交易日**，不是自然日：
- 「信号落后几个交易日」才是要度量的量纲；
- 自然日差把周末与假期的**日历长度**混进来了，而日历长度与信息陈旧无关 ——
  周五收盘到周一开盘，市场**没有产生任何新信息**，这与周一收盘到周二开盘完全等价。

### 2.4 三口径实测对比（脚本 `scripts/verify_freshness_caliber_options.py`）

| 场景 | A 自然日差（现行） | B `busday_count` | C 交易日历 lag |
|---|---|---|---|
| 周一，信号=周五 08-28 | **3 → ⛔ 误伤** | 1 → ✅ | **0 → ✅** |
| P0-3 真病灶：08-25 用 08-21 信号 | 4 → ⛔ | 2 → ⛔ | **1 → ⛔ 正确拦截** |
| 假期后首日（如国庆后） | ⛔ 误伤 | **⛔ 误伤**（法定节假日被算作工作日） | **0 → ✅** |

**只有 C 同时满足**：放行全部「标准 T+1」，拦截真正的缓存停更。

### 2.5 全历史影响面实测（不是估算）

构造**健康态样本**：遍历交易日历每一对相邻交易日 `(today=cal[i], signal=cal[i-1])`——
即「盘前刷新正常执行、信号恒为上一交易日」这一**本该 100% 放行**的场景，共 **2097 天**（2018-01-02 ~ 2026-08-28）。

| 口径 | 阈值 | 误拦天数 | 误拦率 | 判定 |
|---|---|---|---|---|
| A 自然日差（P3-B 现行） | 1 | **448 / 2097** | **21.36%** | ⛔ |
| B `busday_count` | 1 | **60 / 2097** | **2.86%** | ⛔ |
| C 交易日历 lag | 0 | **0 / 2097** | **0.00%** | ✅ |

**A 误拦的 448 天构成**：周一 410 天 + 假期后首日 38 天。
按年稳定在 **20.7% ~ 23.1%**（2018~2026 逐年：50/52/52/52/50/51/52/53/36 天）。

**B 残留的 60 天全部是法定假期后首日**（春节/国庆为主），每年 **6~8 天**：

```
2020-02-03(Mon) 信号=2020-01-23   A=11  B=7(拦截)  C=0(放行)
2023-10-09(Mon) 信号=2023-09-28   A=11  B=7(拦截)  C=0(放行)
2024-02-19(Mon) 信号=2024-02-08   A=11  B=7(拦截)  C=0(放行)
2026-02-24(Tue) 信号=2026-02-13   A=11  B=7(拦截)  C=0(放行)
```

> 这组数据把「选项 2 退回 B」的定位钉死了：**它能修掉 410 个周一，但修不掉每年 6~8 个长假后首日。**
> 而长假后首日恰恰是**波动最大、最需要主源信号**的交易日。

## 三、C 口径定义（建议方案）

```python
# 交易日历 = 主湖实际存在的交易日（无需外部依赖，不受 MCP 可用性影响）
calendar = sorted(实际存在于 data/raw/processed/<sym>/1d/*.parquet 的日期)

prev_trading_day = max(d for d in calendar if d < today)
lag = calendar.index(prev_trading_day) - calendar.index(signal_date)

# lag = 0 → 信号即上一交易日的收盘信号 → ✅ 放行（标准 T+1）
# lag ≥ 1 → 信号落后 N 个交易日          → ⛔ 拦截（缓存停更，P0-3 病灶）
```

**阈值 = 0**（语义：信号必须覆盖最近一个已收盘交易日）。

### 为什么这个口径是对的

| 性质 | 说明 |
|---|---|
| 度量对象正确 | 直接回答「信号有没有覆盖最近一个已收盘交易日」，而非「隔了几个自然日」 |
| 与星期几无关 | 周一、周二…周五一视同仁，消除了 20.6% 的系统性误伤 |
| 假期免疫 | 采用湖内实际交易日，法定休市日天然不在序列中，无需额外维护节假日表 |
| 仍防 P0-3 | 缓存停更 1 个交易日即触发拦截，比原阈值 0（不可能达成）更严格且可达 |
| 无外部依赖 | 不依赖 westock-mcp `data_trade_calendar`（当前会话处于 disabled 状态） |

## 四、影响面与紧迫性

- **受影响**：周一日盘（每年 ~52，占误伤 91.5%）+ 假期后首日日盘（每年 ~6 个交易日）。
  合计 **21.36% 的交易日**，且**逐年稳定**（2018~2026 均在 20.7%~23.1%），不是偶发。
- **不受影响**：周二~周五日盘（自然日差 = 1，A 口径也放行）；**全部夜盘**（20:30 刷新后 fd=0）。
- **性质**：这不是「偶尔失效」，是**结构性、可预测、每年复现**的静默降级 —— 系统不会报错，
  只会静默走技术兜底，因此**极易长期不被发现**（今天若非运营反馈，仍会被 fd=3 的反推误导）。
